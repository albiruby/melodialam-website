## 2. Temuan keamanan

Semua temuan berada di **permukaan demo** (`/submit`, `/api/demos`,
`/api/demo-audio`) dan di **secret editorial**. Tidak ada temuan yang
menembus batas data privat `submissions` dari sisi publik.

| # | Temuan | Severity bila terkonfirmasi | Perbaikan terkecil |
|---|---|---|---|
| F01 | `audioUrl` diterima dari host mana pun, lalu disimpan ke dokumen yang dikurasi **dan** dikirim ke email redaksi | **High** | bandingkan host dengan store Blob milik operator; tolak selain itu dengan 422 |
| F02 | `POST /api/demos` tanpa rate limit/quota/CAPTCHA/idempotensi; tiap permintaan = 2 tulis Sanity + 1 email berbayar | **High** | rate limit per IP di edge + Turnstile + `Idempotency-Key` |
| F03 | satu secret (`SANITY_REVALIDATE_SECRET`) dipakai untuk **dua** kapabilitas: baca draf + invalidasi 6 tag cache, dan diterima lewat `?secret=` di URL | **Medium** | `SANITY_PREVIEW_SECRET` terpisah; header saja; rotasi nilai lama |
| F04 | token unggah Blob diterbitkan untuk siapa pun; key objek tidak diikat server; `access: "public"` dipilih peramban; nama file asli ikut ke URL publik | **Medium** | server yang menentukan key + access; bucket privat + signed URL; nama file di-sanitasi |
| F05 | token unggah bisa dicetak tanpa batas → menulis objek ke storage milik operator yang tak pernah dibersihkan | **Medium** | butuh grant sekali-pakai dari `/api/demos` + job pembersihan |
| F06 | tanpa token, antrean fallback dilayani **tanpa** filter status (dtsb. `IN REVIEW` terbaca publik) dan submitten diberi janji "telah masuk antrean" padahal tidak tersimpan | **Low** | filter status di kedua cabang fallback; tanpa store → 503 + log, bukan 201 |
| F07 | hapus submission di Studio meninggalkan `demoContact` (PII) dan objek audio (publik) hidup selamanya | **Low** | aksi hapus kurator yang ikut menghapus kontak + objek; tetapkan tanggal retensi |
| F08 | `visionTool()` aktif di workspace `submissions` → GROQ bebas atas dataset privat bagi siapa pun yang punya akses workspace | **Low** | matikan visionTool di workspace itu; periksa daftar anggota proyek |
| F09 | `DATABASE_URL` berisi password Supabase untuk layanan yang sudah tidak dipakai | **Low–Medium (operasional)** | hapus dari `.env`; rotasi password di akun Supabase |
| F10 | error mentah Sanity ditulis penuh ke log operator tiap kegagalan tulis | **Informational** | log ringkas: status, tipe error, id kiriman |

**Satu kandidat gugur saat verifikasi:** hypothesized stored XSS lewat
`href` Portable Text. Verifikasi independen membatalkan-nya — **React 19.3
membersihkan `javascript:` di `href` pada render server maupun client**
(`react-dom-server.node.production.js:285-291`), dan situs ini tidak punya
sesi/cookie/storage yang bisa dikompromikan. Diturunkan menjadi catatan
hardening: `components/ArticleBody.tsx` sebaiknya meng-override `marks.link`
dengan allowlist skema (http/https/mailto/tel) — aturan `Rule.uri` di Studio
hanya berlaku di form, bukan di Content Lake.

### Catatan hardening lain (bukan temuan)

- `lib/sanity-server.ts` dan `lib/sanity-preview.ts` memegang token tetapi tidak
  memakai `import "server-only"`. Graf impor sudah dijaga (tidak ada
  `"use client"` yang menyentuh keduanya) — tapi penanda itu menjadikannya
  jaminan build-time, bukan konvensi.
- `xml()` di `app/rss.xml/route.ts` belum membuang karakter terlarang XML 1.0
  (U+0000–U+001F), jadi satu judul berisi karakter kontrol membuat seluruh feed
  tidak valid.
- `fromCms` tidak mem-type-check `imagePath`; satu dokumen rusak bisa
  menggagalkan seluruh `/rss.xml` (bukan hanya halamannya).
- `components/VideoModal.tsx` memvalidasi `id` dari event `melodi:watch` hanya
  dengan cek non-kosong sebelum menyisipkannya ke URL embed YouTube. Hostnya
  tetap terkunci, jadi dampaknya kecil — tapi id sebaiknya dicocokkan dengan
  `/^[\w-]{11}$/`.

## 7. Rencana tindakan (urutan)

**P0 — sebelum nyalakan fitur baru**

1. Pasang **Blob store** di Vercel → `BLOB_READ_WRITE_TOKEN` ikut terpasang, lalu
   perbaiki `app/api/demo-audio/route.ts`: server yang menentukan key + access,
   dan `app/api/demos/route.ts` menolak `audioUrl` dari host asing.
2. **Rotasi `SANITY_REVALIDATE_SECRET`**, pasang `SANITY_PREVIEW_SECRET` terpisah,
   dan hapus penerimaan `?secret=` di kedua rute.
3. Tambahkan **rate limit** untuk `POST /api/demos` + `POST /api/demo-audio`
   (Vercel Firewall atau bucket di rute), plus `Idempotency-Key`.
4. Hapus `DATABASE_URL` dari `.env` dan rotasi password Supabase-nya.

**P1 — konsistensi & kejujuran dokumen**

5. Centang **Update** di webhook Sanity; samakan filternya ke 8 tipe.
6. Perbarui `docs/SECURITY-PRIVACY.md` §4.11 (tidak ada PII tersimpan / tidak
   ada audio diunggah — keduanya sudah tidak benar), naikkan SEC-F02 di tabel
   ringkasan, dan koreksi `docs/SANITY-INTEGRATION.md:382`.
7. Hapus export mati: `demoStoreConfigured`, `draftPreviewConfigured`,
   `videosByIds`, `videosByVenue`; cabut `cardCurtain.featureLabel/featureCta`
   dari skema Studio.
8. Tambahkan `import "server-only"` pada `lib/sanity-server.ts` dan
   `lib/sanity-preview.ts` (+ dependensi `server-only`).

**P2 — polish**

9. Pasang `RESEND_API_KEY` → notifikasi email hidup; set `DEMO_NOTIFY_TO`.
10. Aktifkan Vercel Web Analytics di dashboard.
11. Lampirkan domain `melodialam.id` → semua canonical ikut benar.
12. Tambahkan `script-src` pada CSP enforced; allowlist skema pada
    `marks.link` di `components/ArticleBody.tsx`; `typeof` check untuk
    `imagePath`; buang karakter terlarang XML di `xml()`.
